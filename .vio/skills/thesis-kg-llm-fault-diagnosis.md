## 3. 系统架构（论文按此写）

三段式诊断（入口：`app/server.py` 流式 `/chat` 的诊断分支，另有非流式分支）：
1. **知识图谱子图检索**：Neo4j，节点为 区域-设备-部件-故障-原因-措施 六元组，关系带 `source_row` 用于溯源；前端用 Cytoscape 展示。
2. **相似记录检索**：`app/diagnosis/unified_retrieval.py`。按 字面覆盖度（二元字组，IDF 加权）×0.65 + bge-m3 向量相似度×0.35 召回 top-N（15 条）。bge-reranker 交叉编码器精排是可选开关，**默认关闭**（见第 8 节第 0 条）。
3. **排查决策树生成**：`server.py: build_diagnosis_flow_plan()`
   - **有网络**：调用大模型（`_build_flow_plan_with_llm`），输入图谱链路（每行「部件 → 故障 → 原因 → 措施」+ 出现次数，`unified_retrieval.kg_chain_evidence`）和前 6 条相似记录，输出 JSON DSL 决策树。提示词 `flow_plan_prompt_zh/_en`（`app/settings/settings_router.py`），v2 已锁定。大模型只负责挑原因，分支顺序由 `_sort_branches_quick_cheap` 按成本等级确定。
   - **无网络**：用规则生成决策树（`unified_retrieval.build_decision_tree`）。做法是按原因分组，按“相关度×出现次数”选出主要原因，再按处理成本从低到高排序。
   - 判定无网络的方式：`_llm_reachable()` 在 3 秒内建立不了到大模型服务的 TCP 连接（结果缓存 30 秒），或者调用时连接失败/超时；设置页的“模拟断网”开关也会直接判为无网络。大模型输出无效时同样改用规则，原因记为“大模型输出无效”。
   - 返回结果里带 `generator: llm | rule` 和 `fallback_reason`，流程图标题旁显示“大模型生成 / 规则生成”。
   - **用户明确定义：流程图就是决策树。有网时由大模型生成，无网时按规则生成。不要写成“大模型优先 / 规则降级”或“在线 / 离线”。**

两路检索相互独立，到第 3 段才由大模型汇合。论文写成“双路证据检索 + 大模型融合生成”，不要写成“图谱引导检索”。
