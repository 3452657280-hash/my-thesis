## 与开题报告/旧描述不一致、写论文时要注意的点

1. **LangGraph**：`create_graph()`（server.py:2877-2919）定义了 router→diagnosis/generate，但只在非流式请求里 `graph.invoke`（4714）；前端默认的流式路径按相同步骤手动调用函数。论文写“用 LangGraph 定义流程，流式接口按同样步骤依次调用”，不要夸大。
2. **意图分类**：原流式流程调用 `_classify_kg_intent()` 但结果未使用；6748d66 已删掉这次调用（省一次大模型调用）。论文不写意图分类。
3. **路由**：`route_policy` 目前所有问句都走 diagnosis（route_policy.py:58,77）。
4. **graphrag/ 多跳遍历**已在主流程注释停用（server.py:2432-2449），不写进论文。
5. **登录是模拟的**（App.jsx:29 isAuthenticated=true），角色存在 localStorage。CytoscapeGraph 的编辑/合并按钮已在 6748d66 改为只对 engineer/admin 显示；后端接口本身没有鉴权（原型限制，论文如实写）；回滚 UI 在 Neo4jGraph.jsx 中，但该组件未渲染。后端回滚接口完整（server.py:4376-4618）。论文写“基于角色的编辑权限”前需补上前端检查，或如实写为原型限制。
6. 图谱可视化是 **Cytoscape.js + fcose**；ECharts 只在旧组件里作兜底。决策树用 **Mermaid** 渲染。前端没有 antd，用 Tailwind。
7. sentence-transformers 被 reranker.py 使用但不在 requirements.txt。

## 后端摘要
- 接口分组：/chat（SSE，帧 type：meta、route、diagnosis_kg、diagnosis_records、diagnosis_flowchart、content、progress、done、error）；/conversations；/graph（查询、节点/边增删改、merge、mutations 回滚、CSV 导入导出）；/flowcharts；/api/datasets（嵌入、集合、Neo4j 统计/导入导出/清空）；/settings（prompts+history、language、diagnosis、llm）；/api/ocr。
- Neo4j：标签 Area/Equipment/Component/Problem/Cause/Solution；关系 INCLUDE/HAS_PART/HAS_FAULT/CAUSED_BY/SOLVED_BY；关系属性 source_row（年份#行号）、year；节点 name 为 MERGE 键；Equipment 台账属性 brand/model/sn/process/line/segment。无部件时 Equipment-HAS_FAULT→Problem。
- Qdrant：集合 23、23-2、24、25（collection_registry.json），1024 维，余弦；payload：record_id、line、station、problem、cause、action、plan、date、source_year、source_row、source_row_hash、source_file。
- SQLite：conversations(conversation_id,title,message_count,last_activity,created_at)；messages(id,conversation_id,role,content,timestamp,qdrant_records,extra_payload)；flowcharts(id,title,query,mermaid_code,flow_plan,records,created_at)。
- 图谱变更日志：data/output/graph_mutations.jsonl（mutation_id,timestamp,action,target,request,inverse），回滚按 inverse.action 五种：delete_node、restore_node_state、recreate_node、delete_edge、recreate_edge。
- 配置：diagnosis_config.json、prompts_config.json + prompts_history/、.env。
- 流式诊断调用链：chat → is_followup → route_query → (英文则翻译) → unified_retrieval.run[retrieve(parse_query, 字面+_vector_scores) → 可选 _rerank_chains → select_graph_chains/build_graph → build_records → build_decision_tree] → 推 diagnosis_kg、diagnosis_records → build_diagnosis_flow_plan[_llm_reachable 3s TCP 探测/缓存30s/simulate_offline；_build_flow_plan_with_llm 超时45s；失败→规则] → 推 diagnosis_flowchart → 存 SQLite → done。
- 依赖：fastapi 0.109.0、uvicorn 0.27.0、langchain/langchain-openai、langgraph、qdrant-client、neo4j≥5.21、transformers、torch。
